# Architecture

## Overview

Mini App Runtime has three layers:

```text
HTML mini-app or launcher interface
        │
        ├── runtime.js / launcher-runtime.js
        │
Native Android or Windows host
        │
Local mini-app files, settings, and platform services
```

Mini-app pages use `mini.*`; trusted launcher interfaces use `launcher.*`. The JavaScript bridges serialize calls to JSON messages. Each native host validates the request, performs the permitted operation, and resolves or rejects the corresponding Promise.

## Hosts

Android is a Kotlin application built with Android Gradle Plugin. It uses Android WebView, stores shared content under `/storage/emulated/0/MiniApps`, and exposes Android-specific services such as notifications, directory access, and haptics.

Windows is a .NET 10 WinForms application using WebView2. It uses virtual host mappings for local HTML content and keeps its complete runtime state next to `MiniApps.exe`. The published application is framework-dependent, single-file, and uses the system WebView2 Runtime.

## Content and installation

`DefaultContent/Interface` and `DefaultContent/MiniApps` are Windows package inputs. During publishing, launcher themes go under Interface, shared modules go under MiniApps/Modules, and bundled app archives go under Data/BundledMiniApps. On startup Windows applies those archives through the package installer.

Mini-app installation is manifest-based. The host validates a package, stages it outside the active app tree, and replaces the active directory only after validation succeeds. The stable `manifest.id` identifies the app; public `storage.json` is retained during an update. Both hosts can retain one previous package. Replacement intent is written before switching directories so interrupted changes can recover on startup.

## Trust boundaries

Mini-apps receive opaque file and directory capability IDs, never host paths. Permissions are declared in the manifest and stored per `manifest.id`. Secure storage is encrypted by the platform and is not shared or included in ordinary backups. Controlled network requests use a manifest allowlist and are separate from browser `fetch`.

A stable per-app HTTPS origin isolates browser storage. The host separately
scopes native permissions and data to the installed app ID. Android verifies
the origin and main frame of incoming bridge calls.

## Telegram integration

The native integration registers the Telegram functions used by the
bundled sign-in provider, permitted consumers and Telegram Cloud.
The provider loads its trusted package. The handler owns session consent,
connection leases and provider-specific behavior. Cloud registers its
channel, thumbnail and menu operations on the same function bridge.

The common runtime dispatches registered names and reports them through
`mini.runtime.supports`. Bundled apps call the operations through
`mini.functions.call`. The stream bridge receives deadlines for active
sources.

## Build outputs

`Build/` contains durable build configuration and scripts. `Cache/` holds regenerated outputs. `Output/` holds distributable files only. The Windows script builds the installer; the Android script builds the release APK.


# Interface module

The launcher interface is an externally editable HTML/CSS/JavaScript module. The runtime adds the small bridge automatically; `index.html` only needs its own markup and scripts.

On Android it is created at:

```text
/storage/emulated/0/MiniApps/Interface
```

`Interface` is a collection of launcher themes. Each subfolder is one interface and must contain `index.html`; it may be a self-contained HTML file or a set of HTML/CSS/JS files. The active interface is selected in **Settings → Interface**. ZIP and HTML files placed directly in `Interface` are scanned into interface folders; the same formats can be added through the native file picker.

Both hosts package Default and Metro from `DefaultContent/Interface`. Each theme has one self-contained `index.html` with English and Russian dictionaries. Android loads the built-in pages from the APK. Windows loads the pages installed in the interface folders. Both reserve the IDs `default` and `Metro-Interface` and keep per-theme settings in the interface folder. Imported ZIP or folder interfaces may include additional files referenced by their `index.html`.

On Windows it is created beside `MiniApps.exe` in the selected installation folder:

```text
<installation-folder>/Interface
```

The same `Interface/<name>/index.html` layout, active-interface selection, root HTML/ZIP scan, and native import are supported on Windows.

On Windows, the installer packages every interface from `DefaultContent/Interface`. Each interface is a folder with `index.html`; the default package is `DefaultContent/Interface/default/index.html`. Custom installed interface folders are preserved unless their packaged files share the same path.

If the selected interface is removed outside the runtime, Android selects Default on the next launch. Windows selects the first remaining valid interface alphabetically. A valid interface is a subfolder containing `index.html`.

## Language

Select English or Russian in the launcher settings. In Metro, the control is
under **Personalization**. In Default, it is under **About**. On first launch,
MiniApps uses Russian for a Russian system locale and English otherwise.
The preference is saved per installation. On reload, Default and Metro read
`launcher.getLanguage()` and select their dictionary in the same HTML page.
Labels, accessibility attributes, menus, and formatted values use that language.

Custom launcher interfaces can read `launcher.getLanguage()` and use
`launcher.mountLanguageSettings(container)` to add the selector. Their own
markup and translation dictionaries remain inside the interface package.
Mini-apps receive the selected language on their next launch.

## Windows launcher controls

- Click an app card to open it in the main window.
- Right-click an app card to open the launcher context menu with **Open** and **Open in new window**.
- Middle-click an app card to open it in a separate window.
- The app view in the main window provides a **← Back** button to return to the launcher.
- When an additional app window is open, closing the main window hides it in the notification area. Double-click the tray icon or choose **Open** to restore it; choose **Exit** to exit.

The built-in WebView2 context menu is disabled so it does not override the launcher menu.

## Native top bar configuration (Windows)

When an interface provides an appbar, it belongs to that interface: `Interface/<name>/appbar.js` and `Interface/<name>/appbar.css`. It is loaded into mini-apps while this interface is active; the bar itself is rendered by the Windows application.

```js
await mini.ui.setTopBar({
  height: 60,
  title: document.title,
  background: '#12141c',
  foreground: '#f6f7fb',
  accent: '#365bff',
  paddingX: 14,
  paddingY: 10,
  titleFontSize: 11,
  showBack: true,
  backText: '← Back',
  backButton: {
    radius: 20,
    paddingX: 16,
    background: '#5271ff',
    hoverBackground: '#6b86ff',
    foreground: '#ffffff',
    border: '#b7c4ff',
    borderOpacity: 105,
    fontSize: 9.5
  },
  actions: [{ id: 'save', label: 'Save', accent: true }]
});

mini.events.on('ui.topBarAction', id => {
  if (id === 'save') saveDocument();
});
```

Supported fields are `visible`, `height` (40–120 px), `paddingX`, `paddingY`, `titleFontSize`, `title`, `background`, `foreground`, `accent`, `showBack`, `backText`, `backButton`, and up to four `actions`. `backButton` controls the full back-button shape and styling: `radius`, `paddingX`, `background`, `hoverBackground`, `foreground`, `border`, `borderOpacity`, and `fontSize`. Colors must be `#RRGGBB`. The host draws it using a lightweight custom control, so the area outside its rounded shape remains the top-bar background. Use `mini.ui.hideTopBar()` to hide the bar.

Available JavaScript API:

```js
await launcher.list();
await launcher.getAppInfo(appId); // manifest, dates, and size breakdown
await launcher.open(appId);
await launcher.refresh();
await launcher.importApp();
await launcher.openNewWindow(appId); // Windows: separate window
await launcher.getInterfaceSettings(); // JSON object for the active interface, or {}
await launcher.setInterfaceSettings(settings); // JSON-compatible object
```

## Interface settings

The launcher provides a separate **Settings** button with Telegram installation
for themes without their own Telegram settings. To integrate the action into
your own settings, call `launcher.hasTelegramClient()` and
`launcher.installTelegram()`, and add `data-miniapps-telegram-settings` to
the root `<html>` element.

`launcher.getInterfaceSettings()` and `launcher.setInterfaceSettings(settings)` store settings for the active launcher interface on Android and Windows. Each interface owns `Interface/<active-interface-id>/settings.json`; the native host derives this path from the selected interface, so interface JavaScript cannot choose another destination.

The getter returns `{}` when the file is absent, unreadable, malformed, or contains a non-object JSON value. The setter accepts only a JSON object, serializes at most 64 KiB (UTF-8), and replaces the file through a flushed temporary file and atomic rename. Switching interfaces changes the settings file used by subsequent calls. Removing or replacing an interface directory also removes its settings with that directory.

## Common mini-app strip

Runtime adds two standard header files to the same folder:

```text
Interface/
├─ appbar.css
└─ appbar.js
```

They automatically connect to all pages of every mini-app on Android and Windows. By default, the bar is fixed at the top of the window and contains the `← Back` button.

Clicking this button returns to the launcher: on Android it closes the current Activity mini-app, and on Windows it returns to the main window. If the mini-app was opened in a separate Windows window, the button closes this window.

Modify `appbar.js` and `appbar.css` to add any buttons, labels or custom logic to the strip. These files run in the context of each mini-app and have access to `mini.*`.

## Windows windows

A simple click on the mini-app opens it in the same main window. On Windows, you can open the application separately:

- middle mouse button on the mini-app card;
- the item `Open in new window` in the context menu of the card;
- via `await launcher.openNewWindow(appId)` in the JavaScript of the launcher interface.

## Updating an existing Interface

The Windows installer updates the interface files from `DefaultContent/Interface/`. Additional user interface folders in the installed program are not deleted; runtime does not copy the legacy template from `Code/Framework/shared/launcher-interface/`.

## System API compatibility

Interface code should call `mini.runtime.supports(name)` before presenting controls for optional system features. `mini.ui.setTopBar()` remains available on Windows. Controlled HTTP, file handles, native dialogs, clipboard reads, and external opening must use their `mini.*` APIs rather than relying on browser privileges.

Do not present notification or haptics controls in a Windows launcher interface without checking capabilities. Android notification actions may open a mini-app with `mini.app.getLaunchParams()` containing a notification ID and payload; Windows currently supplies only the normal launch context.


# Using the launcher

For the update rules and the Windows rollback and permission APIs, see
[Package management](mini-app-management.md).

## Application information

`launcher.getAppInfo(appId)` is available to Android and Windows launcher interfaces. It returns the selected app's manifest, installation and update timestamps, and application and data sizes.

Both hosts support these launcher operations: `list`, `open`, `refresh`, `importApp`, `deleteApp`, `shareApp`, `shareAppData`, and `getSettingsInfo`; Windows additionally supports `openNewWindow`. The interface manager provides `listInterfaces`, `selectInterface(id)`, `importInterface()`, `getInterfaceSettings()`, and `setInterfaceSettings(settings)`. Interface settings are a JSON object in the active interface's `settings.json`, limited to 64 KiB and written atomically; a missing or corrupted file reads as `{}`.

**Settings → About** shows the installed MiniApps version on Android and Windows. Launcher interfaces read the `version` field returned by `await launcher.getSettingsInfo()`.

On Android, the working folder is `/storage/emulated/0/MiniApps`. The runtime does not import or migrate data from any previous application folder.

Choose **Add app** to import a ZIP or HTML file. For the exact package layout
and scan behavior, see [Mini-app format](mini-app-format.md).

## Built-in mini-apps on Android

The Android APK includes the Android-compatible built-in mini-apps and the Telegram shared module. After a fresh install or an APK update, open MiniApps and grant file access if prompted. MiniApps applies the bundled packages before showing the app list. This includes Shopping List, Unofficial Telegram and Telegram Cloud. If the installed mini-app has a higher version, MiniApps keeps it. A failed package is retried when the launcher next starts.

Install the new APK over the existing MiniApps installation to retain private and secure storage. MiniApps updates each matching app in its existing folder and retains its public data. All languages of an app share its ID and data.

The app-card menu can delete or share an app and share its public `storage.json`. App sharing creates a single HTML file only for a self-contained HTML app with an embedded manifest; otherwise it creates a ZIP containing the app code. User data, including `storage.json`, is excluded. Data sharing exports only public `storage.json`. Deletion also clears private storage and stored permission decisions. Android uses the system Sharesheet with a `content://` FileProvider; Windows copies a file to the clipboard for pasting into Explorer or another application. Windows `mini.share.text()` and `mini.share.file()` also copy their text or file payload to the clipboard. Private storage is never exported.

## Install Telegram

Open **Settings → Telegram** in the launcher and choose **Install Telegram**
or **Update Telegram**. Both builds carry the package files. MiniApps
shows progress while installing the shared module in
`MiniApps/Modules/telegram` and installing or updating **Unofficial Telegram**.
The installer keeps the saved Telegram account. The bundled client is used
for Telegram sign-in. When a newer installed client causes the import to be
skipped, the launcher reports that outcome and leaves the shared module as
it was. This section also contains
**Telegram test server** and **Save Telegram login log to file** on both
platforms. Both settings are stored per installation and are off by default.
The server choice applies when you next open Unofficial Telegram directly.

The **Unofficial Telegram** app card shows the client version. Use the Telegram
settings action to reinstall the included module and client when needed.

Both built-in launcher interfaces include **Telegram** in **Settings**.
Custom interfaces can add the Telegram controls using the launcher API.

After successful installation, choose **Yes** to restart MiniApps immediately
or **No** to keep working. Custom launcher interfaces can use
`launcher.hasTelegramClient()` to label the action in settings and
`launcher.installTelegram()` to open the platform's installer with progress
and restart confirmation. Use `launcher.mountTelegramSettings(container)`
to add the two switches and the login-log viewer to a custom Telegram settings panel.

## Launcher interfaces

On Android, interfaces reside in `MiniApps/Interface/<interface-id>/`; on Windows, they reside in `Interface/<interface-id>/` beside `MiniApps.exe`. Select the active interface in **Settings → Interface**; it is used by both the launcher and mini-app app bars. The built-in `default` contains only `index.html`, with its CSS and launcher JavaScript embedded. HTML and ZIP files placed directly in `Interface/` are scanned as new interfaces; the same import is available from **Add interface**. Folder and ZIP interfaces may contain additional files. An interface-specific mini-app app bar is stored beside the interface as `appbar.css` and `appbar.js`.

If the active interface is removed manually, Android selects Default and Windows selects the first valid interface alphabetically on the next launch. A valid interface folder contains `index.html`.


# Local device presets

Runtime 1.5.0 provides generic LAN discovery and HTTP requests to discovered devices.
Device-specific commands, presentation, pairing and firmware belong to a mini-app
and its device preset. The host has no knowledge of lighting or board models.
This API is available in release builds and does not enable `mini.peers`.

## Manifest and permission

```json
{
  "permissions": ["network"],
  "network": {
    "allow": [],
    "allowHttp": true,
    "allowLocalNetwork": true,
    "discoveryServices": ["my-device"]
  }
}
```

`discoveryServices` contains up to eight service names matching
`[a-z][a-z0-9-]{0,47}`. Empty HTTP origin lists are accepted when a valid
discovery service is declared. Existing HTTP origin rules continue to apply
to `mini.network.request`; discovered devices do not add general URL access.

Both local-device methods require the normal `network` permission. An app can
check the stored decision at launch and immediately discover if it is granted.
For the first use, provide a user control that calls discovery: the host shows
its permission dialog before network access. Never grant permissions silently.

## Bridge

```js
if (await mini.runtime.supports('network.discoverDevices')) {
  const devices = await mini.network.discoverDevices({
    service: 'my-device', timeoutMs: 2500
  });
  // [{ id, deviceId, name, service }]
  if (devices.length === 1) {
    const response = await mini.network.requestDevice({
      id: devices[0].id, path: '/api/state', method: 'GET',
      token: savedToken, timeoutMs: 4000
    });
    // { status, ok, body: { encoding: 'text', data: '...' } }
  }
}
```

`id` is an opaque capability owned by this app view. It expires 60 seconds after
the last successful discovery and never exposes an address or port. Rediscover
every 20 seconds while connected. `deviceId` is an untrusted device-generated
32-character lowercase hex identifier, useful for reconnecting to a previously
selected device; it must not be treated as authenticated identity.

Discovery returns up to 64 matching responders for the current query, including
all available interfaces. An empty result means no device replied. Timeout is
1000–5000 ms (default 2500). One discovery can run per app view. It binds to up to
eight active private IPv4 interfaces, sends directed broadcasts and, on /24 or
smaller subnets, performs a paced unicast fallback over all usable addresses.
There is no fixed `.1`–`.200` cutoff. Larger subnets require broadcast delivery.
Windows discovery disables UDP `PORT_UNREACHABLE` error reporting on its probe
socket: closed ports on other hosts must not stop reception of device replies.
Guest-network isolation, VLAN boundaries, firewalls and disabled broadcasts can
prevent discovery even when two devices use the same router. IPv6-only and public
address LANs are not supported by this protocol.

Requests permit GET and POST, timeout 1–10000 ms (default 4000), a relative path
matching `/api/[a-zA-Z0-9_/-]{1,80}` (no `//`), and an optional form-encoded string
`body` up to 4096 UTF-8 bytes. GET bodies are rejected. The optional `token` is
32 lowercase hex characters and is sent as `X-Device-Token`. POST uses
`application/x-www-form-urlencoded; charset=utf-8`. No redirects, cookies, proxy,
arbitrary headers or caller URLs are supported. Response body limit is 64 KiB.
The Android reader also limits response headers to 8 KiB. Devices must return
HTTP/1.0 or HTTP/1.1 with one `Content-Length`, without chunked transfer encoding.
App close cancels discovery/request resources and invalidates capabilities.

Errors include `network_url_not_allowed`, `invalid_params`, `network_unavailable`,
`discovery_busy`, `device_busy`, `device_not_found`, `network_timeout`,
`network_request_failed`, `network_redirect_blocked`, `network_response_invalid`
and `network_response_too_large`. HTTP failures such as 401 are returned as
responses; the mini-app decides how to handle them.

## Device discovery protocol v1

Device listens on UDP **42101**. Datagrams are ASCII with exactly one space between
fields, without a trailing newline. Runtime creates a fresh 32-character lowercase
hex nonce per discovery and sends:

```text
MINIAPP_DEVICE/1? <nonce> <service>
```

A matching device replies **from port 42101**, unicast to the sender's address and
ephemeral port:

```text
MINIAPP_DEVICE/1! <nonce> <service> <deviceId> <httpPort> <name>
```

`httpPort` is 1–65535. `name` matches `[A-Za-z0-9_-]{1,48}`. Reply size is at most
256 bytes. The host validates nonce, service, sender port and membership in the
queried private IPv4 subnet, and derives the endpoint exclusively from the packet
sender. The packet cannot supply a URL or an alternate host. Discovery is not
authenticated: device-level pairing and authorization still belong to the preset.

HTTP transport is plaintext and is intended for a trusted local network. Tokens
authorize commands but do not provide encryption or protection from an active
LAN attacker. Pairing secrets should be stored with `mini.secureStorage`, never
portable/public storage. Android uses a bounded direct socket for this endpoint
capability; the application and WebView cleartext policy remains disabled.

## Verification

Build Windows with `Build\Scripts\BuildWindows.cmd`, then run
`Build\Scripts\TestLocalDevices.cmd Windows` against its actual compiled service.
`Build\Scripts\TestLocalDevices.cmd Android` runs JVM tests of the production
Kotlin service and manifest parser without creating or signing an APK. These
tests use real UDP and TCP simulators on an active private IPv4 interface;
absence of that interface is a setup failure, not a successful skip. Android APK
distribution still requires the configured permanent signing credentials.

For a locally installable APK without production credentials, use
`Build\Scripts\BuildAndroid.cmd Local`. The SDK signs it automatically with its
persistent debug certificate; the artifact is `Output/Android/MiniApps-local.apk`.
This still uses the release build type, so development-only peer transport stays
disabled. The default build continues to require the configured permanent key.


# Mini-app format

On Android and Windows, the launcher imports ZIP archives and single HTML
files. The file picker accepts those files. To use an unpacked app, place
its folder directly in the runtime's `MiniApps` directory with the manifest
at the folder root. The directory is `/storage/emulated/0/MiniApps` on
Android and `MiniApps/` beside `MiniApps.exe` on Windows.

## Folder and ZIP layout

An unpacked mini-app has this layout. When you create a ZIP, archive the
contents so `manifest.json` is at the ZIP root.

```text
example-mini-app/
├── manifest.json
├── index.html
├── app.js
├── style.css
└── assets/
```

Minimal `manifest.json`:

```json
{
  "id": "com.example.demo",
  "name": "Demo App",
  "version": "1.0.0",
  "sdkVersion": 1,
  "entry": "index.html"
}
```

Supported fields:

```text
id
name
version
sdkVersion
minRuntimeVersion
entry
description
author
icon
permissions
network
```

Shared JavaScript libraries live separately in `MiniApps/Modules/<id>/index.js`.
The `Modules` directory is reserved and is skipped by the app scanner.
Apps opt in by calling `mini.modules.load(id)`. Declare `telegram.session`
when an app offers shared Telegram sign-in. Optional integrations can wait
until the user opens their Telegram settings or selects Sync.
See [Shared modules and Telegram](telegram.md).

Supported permissions:

```text
storage
clipboard.write
files.pick
files.save
share
secureStorage
network
notifications
clipboard.read
files.directory
system.open
haptics
local.peers
telegram.session
```

The `icon` field can point to a PNG/JPG file inside the mini-app folder:

```json
{
  "icon": "assets/icon.png"
}
```

Paths must be relative, without `..`, without absolute paths and without going beyond the mini-app folder.

## Importing and updating ZIP packages

The installer uses `manifest.id` to identify the app. For example, on a
fresh installation a package whose ID is `com.example.demo` is installed
under `MiniApps/com.example.demo/`, even if its ZIP is named `demo.zip`.

On update, the installer finds the existing folder by manifest ID and keeps
that folder. It accepts the same or a newer SemVer version and preserves
`storage.json` and `storage.json.bak`. An older or invalid package leaves the
installed app in place. Close any open windows of the app before updating it
on Windows.

The picker leaves the selected ZIP at its original location. If you place
the ZIP directly in `MiniApps` and scan that directory, the host removes the
ZIP after a successful import. Sharing creates a new package from the
installed app's code and excludes user data.

## Single-file HTML

One HTML file can contain manifest within itself:

```html
<script type="application/miniapp+json">
{
  "id": "com.example.hsv",
  "name": "HSV Editor",
  "version": "1.0.0",
  "sdkVersion": 1,
  "description": "Single-file HSV color editor",
  "permissions": ["storage", "clipboard.write"]
}
</script>
```

`entry` can be omitted. During installation, runtime will name the HTML file based on the `name` field of the manifest: for example, `HSV Editor.html`, and write this name to `entry`. Invalid characters for the file name are replaced with `_`.

For example, the HTML above is installed as:

```text
MiniApps/com.example.hsv/
├── manifest.json
└── HSV Editor.html
```

## Localized mini-app packages

Keep translation dictionaries inside the mini-app package. Use one HTML page
and select its dictionary using `preferred` from `await mini.locale.get()`.
Set the document's `lang` to the chosen language. All languages share the same
app ID, permissions, version, storage and Telegram connection. Use the manifest
to translate the name and description displayed by the launcher:

```json
{
  "id": "com.example.notes",
  "name": "Notes",
  "version": "1.0.0",
  "sdkVersion": 2,
  "entry": "index.html",
  "translations": {
    "ru": { "name": "Заметки" }
  }
}
```

`translations` is optional and works in ZIP manifests and embedded manifests.
Its supported keys are `en` and `ru`. Each translation contains `name`,
`description`, or both. A missing field uses its top-level value. Translated
names and descriptions must be nonblank strings of at most 256 and 1024
characters, respectively. The top-level `entry` determines the page for
every language.

Keep translated UI text separate from user content. Bundle every dictionary
with the page so switching works offline. Importing an update with the same
app ID preserves its data.

## HTML without manifest

When importing an HTML file without an embedded manifest, the launcher can ask you to supply its metadata.

The dialog accepts these fields:

- App ID
- Name
- Version
- Description
- Author
- Permissions

After confirmation, the file is installed as a regular mini-app:

```text
MiniApps/<app-id>/
├── manifest.json
└── <application name>.html
```

The dialog validates the app ID, required fields and permissions before installation.

## Storage

`mini.storage.*` is private by default.

Public data is written explicitly via `mini.storage.public.*` to the file:

```text
MiniApps/<mini-app folder>/storage.json
```

## System permissions and network policy

Alongside the existing permissions, manifests may declare `network`, `notifications`, `clipboard.read`, `files.directory`, `system.open`, and `haptics`. New permissions are prompted after an update and are never granted automatically.

Controlled HTTP requests require both the `network` permission and an explicit allowlist:

```json
{
  "permissions": ["network"],
  "network": {
    "allow": ["https://api.example.com", "https://*.example.com"],
    "allowHttp": false,
    "allowSubdomains": false,
    "allowLocalNetwork": false
  }
}
```

Only exact origins and leading host wildcards are accepted. `*.example.com` does not include `example.com`. HTTP and local/private addresses require their corresponding explicit flags. The policy applies only to `mini.network.request`, not browser `fetch`.

## Notifications

Android mini-apps may declare `notifications` and schedule a one-time notification with `at`, a daily/weekly local-time schedule, or an `interval` from 15 minutes to seven days. Notification payloads must be JSON and are limited to 16 KiB. Windows declares the same permission for manifest compatibility but reports notification scheduling unavailable through capabilities.

## Discovery-only local device policy (1.5.0)

`network.discoveryServices` is an optional list of up to eight generic service names matching `[a-z][a-z0-9-]{0,47}`. A discovery policy requires the `network` permission and both `allowHttp: true` and `allowLocalNetwork: true`. `network.allow` may be empty when valid discovery services are declared; ordinary `network.request` continues to require an allowlisted origin. This creates no wildcard permission to arbitrary LAN URLs. See [Local device presets](local-devices.md).


# Package management

See [Using the launcher](launcher-management.md) for the app-card and theme controls.

## Install and update

Importing a package with the same `manifest.id` and version replaces the active
mini-app, which allows a corrected package to be delivered without a version
bump. Packages with an older version are rejected. Updates preserve public
`storage.json` and `storage.json.bak` on both platforms.

Both hosts apply bundled packages through the normal package installer
during startup. Android waits for shared-folder access. The installer
validates the ID and version, preserves app data and recovers interrupted
replacements. Android records consumption of scanned files and bundled
updates with the installation so restart can finish the same operation.

`refresh()` scans packages placed directly in `MiniApps`. Picker imports install
the selected package directly; the runtime does not retain a second source copy.

## Windows rollback and permission APIs

Trusted launcher interfaces on Android and Windows can call `launcher.getAppInfo(appId)` to obtain the selected app's manifest, installation and update timestamps, and application/data size breakdown. On Windows, trusted launcher interfaces can additionally call:

- `launcher.getRollbackInfo(appId)` — returns `{ available, currentVersion, previousVersion, createdAt }` when a retained version exists.
- `launcher.rollbackApp(appId)` — validates and swaps the active and retained app directories.
- `launcher.deleteRollback(appId)` — removes only the retained version.
- `launcher.getAppPermissions(appId)` — returns declared permissions with their `granted`, `denied`, or `prompt` state.
- `launcher.setAppPermission(appId, permission, state)` — changes a declared permission to `granted`, `denied`, or `prompt`.
- `launcher.resetAppPermissions(appId)` — restores all permission decisions to `prompt`.

Rollback preserves public, private, and secure user data. This avoids accidental data loss, but an older app version can be incompatible with current data and must handle its own migration. Only one previous version is retained. Close all windows of a Windows mini-app before updating, rolling back, or deleting it.

Android uses equivalent repository-level rollback metadata and swaps, but these launcher methods are not yet exposed to its custom launcher interface. Do not show rollback controls without feature detection.

## Permission decisions

The launcher permission manager displays all manifest-declared permissions, including `network`, `notifications`, `clipboard.read`, `files.directory`, `system.open`, and `haptics`. When an app update adds one, its decision is left at `prompt`; when an update removes one, the stored decision is deleted. Decisions remain isolated by `manifest.id`.

Windows stores permissions by stable app ID. When migrating a legacy
display-name record, the host preserves denials and requests fresh consent
for grants.

Deleting an Android mini-app cancels its scheduled notifications and clears its folder aliases, notification records, permission decisions, public source, and private data. A system folder grant is kept while another alias or open runtime still uses it. Updating an app with the same `manifest.id` preserves its notification records.

## Reserved backup and restore APIs

`createBackup`, `inspectBackup`, and `restoreBackup` are reserved. The
current hosts have no complete backup or restore flow. Keep those controls
hidden until the host reports support for `backup.restore`.

The planned `miniapps-backup` ZIP format uses a version 1
`backup-manifest.json` and per-app entries for source, public data, private
data, and permission decisions. Restore is planned to be atomic per app,
with `replace` and `skip` choices after checking conflicts (`not_installed`,
`same_version`, `backup_newer`, `installed_newer`). The trusted launcher
would own selection and confirmation. Secure storage is excluded.


# Local peer connections

`mini.peers` is the reserved opaque bridge for local device discovery and peer
connections. It is intentionally separate from `mini.network`: mini-app code
does not receive an IP address, network interface, port, socket, MAC address,
SSID, or a host filesystem path.

## Permission and availability

An app declares `local.peers` in its manifest and uses the normal
`mini.permissions.query('local.peers')` / `request('local.peers')` flow. The
permission is never granted automatically. The native transport is available
only in development builds. Release builds report `peers` as unavailable and
reject peer methods with `feature_unavailable`. Use
`mini.runtime.supports('peers')` before displaying peer controls.

```js
if (await mini.runtime.supports('peers')) {
  await mini.peers.startDiscovery();
  const peers = await mini.peers.list();
}
```

## JavaScript contract

The bridge provides `startDiscovery`, `stopDiscovery`, `list`, `connect`,
`disconnect`, `connections`, `openChannel`, `closeChannel`, `sendMessage`,
`sendFile`, `acceptFile`, `rejectFile`, `cancelTransfer`, and `transfers`.
All methods are Promise-based and all options are JSON-compatible. Peer events
are delivered through `mini.events`: `peers.changed`,
`peers.connectionRequested`, `peers.connectionChanged`, `peers.channelOpened`,
`peers.channelClosed`, `peers.message`, `peers.fileOffered`,
`peers.transferProgress`, `peers.transferCompleted`,
`peers.transferCancelled`, and `peers.transferFailed`.

The intended transport is mDNS/DNS-SD discovery of `_miniapps-peer._tcp.local`
and a framed local TCP connection. When a mini-app calls `startDiscovery` again
(the bundled app does this from **Refresh devices**), hosts also send a bounded
UDP fallback probe to addresses `.1` through `.200` of every active IPv4
subnet. The `MAPD1?` probe is answered unicast with a `MAPD1!` device record;
the record contains only the information needed to establish the existing TCP
connection. Logical channels are owned by
`manifest.id + channel name`; hosts must never deliver a channel's messages or
files to another mini-app. File transfers use the existing opaque file and
directory handles, native streaming, bounded chunks, and a final SHA-256
verification; Base64 is not part of the peer-transfer protocol.

The development transport currently has no authenticated pairing or encryption.
Discovery IDs and the TCP handshake do not authenticate a remote device. Do not
use it for sensitive data, even on a private network. Authenticated pairing and
transport protection are required before enabling it in release builds.

Android and Windows encode each post-handshake channel frame as a four-byte
big-endian UTF-8 JSON length followed by the JSON payload. Frames are capped at
64 KiB. The current channel operations use `channel.open`, `channel.close`, and
`message` payloads that carry the owning `appId`; a host accepts an incoming
payload only while that manifest has an active peer listener.

## Bundled demonstration

`DefaultContent/MiniApps/peer-transfer.html` is a single-file HTML demonstration mini-app. It
checks capabilities, requests `local.peers` only from its explicit button,
lists discovered devices, opens a default channel, and displays peer messages.


# Mini App Runtime documentation

Mini App Runtime is a local-first host for HTML mini-apps on Android and Windows. A mini-app is a normal set of HTML, CSS, JavaScript, and assets; the native host adds a small, asynchronous `mini.*` bridge for platform features.

The project is designed for editable, offline-capable mini-apps rather than hosted web applications. It does not bundle Chromium: Android uses the system WebView and Windows uses the installed Microsoft Edge WebView2 Runtime.

## Quick Start

Build a small **Quick Start Notes** app, save a note, then reopen the app to
check that the note persists. The same ZIP works on Android and Windows.

### 1. Open MiniApps

If you already have MiniApps installed, open the launcher. To build a local
copy, run the command for your platform from the repository root:

| Platform | Command | File to install |
| --- | --- | --- |
| Windows | `Build\Scripts\BuildWindows.cmd` | `Output\Windows\MiniAppsSetup.exe` |
| Android | `Build\Scripts\BuildAndroid.cmd Local` | `Output\Android\MiniApps-local.apk` |

See [Requirements](#requirements) for build and runtime dependencies. On
Android, copy the APK to your device, install it and grant MiniApps access to
its shared folder when prompted.

### 2. Create the mini-app

Save these two UTF-8 files in a folder named `quick-start-notes`.

**manifest.json**

```json
{
  "id": "com.example.quickstart.notes",
  "name": "Quick Start Notes",
  "version": "1.0.0",
  "sdkVersion": 2,
  "entry": "index.html",
  "permissions": ["storage"]
}
```

**index.html**

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Quick Start Notes</title>
</head>
<body>
  <h1>Quick Start Notes</h1>
  <label for="note">Note</label>
  <input id="note" disabled>
  <button id="save" type="button" disabled>Save</button>
  <p id="status" role="status"></p>

  <script>
    const note = document.querySelector('#note');
    const save = document.querySelector('#save');
    const status = document.querySelector('#status');

    async function restoreNote() {
      try {
        const permission = await mini.permissions.query('storage');
        if (permission === 'granted') {
          note.value = (await mini.storage.private.get('note')) ?? '';
        }
      } catch (error) {
        status.textContent = 'Could not load the note (' +
          (error.code ?? 'runtime_unavailable') + ').';
      } finally {
        note.disabled = false;
        save.disabled = false;
      }
    }

    save.addEventListener('click', async () => {
      save.disabled = true;
      try {
        await mini.storage.private.set('note', note.value);
        status.textContent = 'Saved.';
      } catch (error) {
        status.textContent = 'Could not save the note (' +
          (error.code ?? 'runtime_unavailable') + ').';
      } finally {
        save.disabled = false;
      }
    });

    restoreNote();
  </script>
</body>
</html>
```

Open the page through MiniApps so the host can inject `mini.*`. On first
launch the example checks permission without opening a prompt. Pressing
**Save** supplies the gesture required for the host to request storage
access. Subsequent launches read the note once that access is granted.

### 3. Import and verify

1. From the directory containing `quick-start-notes`, run this in PowerShell:

   ```powershell
   Compress-Archive -Path .\quick-start-notes\manifest.json, .\quick-start-notes\index.html -DestinationPath .\quick-start-notes.zip
   ```

   The ZIP root must contain `manifest.json` and `index.html` directly.
2. On Android, copy the ZIP to a location you can select in the device's file
   picker. On either platform, open the launcher menu, choose **Add app** in
   the default interface, and select `quick-start-notes.zip`.
3. Open **Quick Start Notes**, type a note, and press **Save**. Confirm
   the storage prompt with **Allow** on Android or **Yes** on Windows,
   then wait for **Saved.**
4. Return to the launcher and reopen **Quick Start Notes**. The note should
   already be in the input field. Its private storage is local to each
   installation, so repeat the save-and-reopen check on each platform.

## Runtime data locations

Android uses `/storage/emulated/0/MiniApps` for installed mini-apps and editable launcher interfaces. Android 11+ requires the system **All files access** permission for direct access to that shared folder.

Windows keeps application state in the chosen installation folder. `MiniApps/` contains installed mini-apps, `Interface/` contains launcher interfaces, `Config/` contains launcher configuration and permission decisions, and `Data/User/` contains private and secure user data. Public mini-app data is the portable `storage.json` file in the mini-app folder.

## Manifest reference

| Field | Required | Description |
| --- | --- | --- |
| `id` | Yes | Stable identifier. Use Latin letters, digits, dots, hyphens, and underscores. |

## Update and sharing behavior

The runtime identifies an installed mini-app by `manifest.id`. Manual imports, packages scanned from the MiniApps folder, and bundled updates on both platforms accept the same version or a newer version. Updates keep public `storage.json` and its recovery copy. Invalid packages leave the active app in place. Sharing exports a self-contained HTML file or a ZIP of application code. Private and secure storage stay on the device.

## Launcher interfaces

Launcher interfaces are editable HTML/CSS/JavaScript packages. The active interface is selected in the launcher settings. Each interface contains `index.html` and may include `appbar.js` and `appbar.css` to configure a mini-app top bar. On Windows, the installer packages the interface and built-in mini-app directories from `DefaultContent/`; additional user interfaces and mini-apps survive installer updates.

# Runtime API v2

Runtime version is `1.5.25`; SDK version 2 is supported. All methods return `Promise` and reject with an object carrying a stable `code`.

`mini.modules.load(id)` loads a classic script from `MiniApps/Modules/<id>/index.js` for ordinary mini-apps. The Unofficial Telegram provider loads its Telegram module from the host bundle.
Check `typeof mini.modules?.load === 'function'` when supporting older hosts.
See [Shared modules and Telegram](telegram.md) for the module layout and trust boundary.

Use `mini.functions.call(method, params)` to call a native function
registered for the current app. Check `mini.runtime.supports(method)`
for optional functions. The host registers functions based on the
installed app ID and its permissions.

### Telegram

A mini-app declaring `telegram.session` calls
`mini.functions.call('telegram.connect', { reauthenticate: false })`
from a user gesture. If necessary, the host opens the bundled Unofficial
Telegram sign-in screen. After sign-in, the requesting app receives the
saved record after native consent. Cancellation rejects with
`operation_cancelled`. Use `reauthenticate: true` to reopen sign-in.

`mini.functions.call('telegram.restoreSaved')` returns a previously
approved record, or `null` when the app needs consent or the session
is missing. The selected Cloud channel uses
`mini.functions.call('telegramCloud.getSavedChannel')` and
`mini.functions.call('telegramCloud.rememberChannel', { id })`.

The Telegram module acquires an exclusive connection with
`telegram.acquire` and an owner token, then calls `telegram.release`
after disconnecting. A busy connection returns `telegram_session_busy`.
The acquire result gives the persisted wait deadline in Unix milliseconds.
`telegram.setWaitUntil` extends it. The Cloud integration passes that
deadline to its active stream sources. Closing the WebView releases its
lease. Standalone Unofficial Telegram also registers
`telegram.acquireTest` for the separate test environment.

The provider's `telegram.getSettings` returns `{ testServer, writeLoginLog }`.
The provider uses `telegram.finishSignIn` after saving the session and
disconnecting during shared sign-in. It also registers
`telegram.setCodeCaptureProtection` for its service chat. Android 14 and
later emit `telegram.screenCaptured` if the OS detects a screenshot.
The provider and Cloud register `telegram.serviceNotices` for the
account's encrypted service notices. See [Telegram](telegram.md).

## Navigation

`mini.events.on('navigation.backRequested', handler)` receives `{ handled() }`. Android system Back/gesture, Windows Escape, native top-bar Back and appbar Back share this route. The host performs the default action after 350 ms when no handler marks the event handled; repeated requests are coalesced. Interception is enabled by default and can be changed with `mini.navigation.setBackEnabled(boolean)`. `mini.navigation.getState()` returns `{ backEnabled }`.

## Capabilities

`mini.runtime.getCapabilities()` returns `runtimeVersion`, `sdkVersion`, `platform`, methods, feature flags and limits. `mini.runtime.supports(name)` accepts a method, feature or event name. Mini-app manifests may declare `minRuntimeVersion` as SemVer. Installation remains possible, but launch is blocked with `runtime_version_too_old` when the runtime is older.

Both `version` and `minRuntimeVersion` use SemVer (`major.minor.patch`, optional prerelease and build metadata). The runtime compares numeric prerelease identifiers according to SemVer rather than using lexical string comparison.

## Application information

`mini.app.getAppInfo()` returns app metadata, using the translated name and description when available, plus ISO-8601 `installedAt` and `updatedAt` timestamps. `appSizeBytes` excludes persistent data; `dataSizeBytes` includes public, private, and secure runtime storage. The separate `publicDataSizeBytes`, `privateDataSizeBytes`, and `secureDataSizeBytes` fields provide a size breakdown.

`await mini.locale.get()` returns `{ preferred }`. `preferred` is the launcher
language (`en` or `ru`) at the start of the mini-app.
The same object is available as `locale` in `mini.app.getLaunchParams()`.
Apps can use `preferred` to choose their own dictionary. A running mini-app
keeps its launch language until it is reopened.

## Storage

Both `mini.storage.private` and `mini.storage.public` provide `getMany`, `setMany`, `getSchemaVersion`, `setSchemaVersion`, and `getUsage`. Schema version starts at 0. Use `mini.storage.transaction({ scope, operations })` for an atomic set/remove/clear/schema update; callback transactions are intentionally unsupported. Public data is written to a flushed temporary file, then atomically replaced; `storage.json.bak` is used for recovery. Corrupt primary and backup data return `storage_corrupted` without silently clearing data.

## Permissions and secrets

`mini.permissions.query`, `request`, and `openSettings` use `granted`, `denied`, `prompt`, `not_declared`, and `unsupported`. A permission must be declared in the manifest. `permissions.changed` is emitted only to the requesting app. `secureStorage` requires the manifest permission of the same name and exposes `get`, `set`, `remove`, `keys`, and `clear`. Android encrypts it with an Android Keystore key; Windows uses user-scoped DPAPI. It is keyed by manifest ID, is not public storage, is not shared, and is not in ordinary backups.

## Runtime logs

`await mini.logs.write(event, fields?)` appends a JSON line to the host's
central `miniapps.jsonl` and returns `{ path }`. MiniApps adds the UTC
timestamp, platform, app ID and app version. The file is in `Data/User/Logs`
under the Windows installation or `Documents/MiniApps/Logs` in Android
shared storage. At 1 MiB the host rotates the file to
`miniapps.previous.jsonl`, retaining one previous file.

Event names and field keys begin with an ASCII letter and contain up to
64 letters, digits, dots, underscores or hyphens. Up to 16 optional fields
can contain strings of up to 256 characters, finite numbers, booleans or
null. A serialized record is limited to 8 KiB. Callers choose diagnostic
metadata and must keep secrets and personal data out of events.

## Events and errors

Events: `navigation.backRequested`, `permissions.changed`, `network.statusChanged`, `app.launchParamsChanged`, `storage.restored`, `app.updated`, `app.rolledBack`. Stable system errors include `feature_unavailable`, `user_gesture_required`, `network_unavailable`, `network_permission_denied`, `network_url_not_allowed`, `network_invalid_url`, `network_timeout`, `network_request_failed`, `network_request_too_large`, `network_response_too_large`, `network_redirect_blocked`, `network_tls_failed`, `notification_permission_denied`, `notification_payload_too_large`, `directory_not_found`, `file_not_found`, `file_too_large`, `file_exists`, `system_url_not_allowed`, and `system_no_handler`.

## System APIs

New manifest permissions are `network`, `notifications`, `clipboard.read`, `files.directory`, `system.open`, and `haptics`. They use the existing `mini.permissions.query()` and `mini.permissions.request()` flow and begin in `prompt` after an update. Native alert, confirm, prompt and toast require no permission. To show a
short message, call `await mini.ui.toast({ message: 'Saved' })`.

`mini.network.request(options)` is the controlled HTTP API. It requires `network` and a `network.allow` manifest list containing exact HTTPS origins or `*.example.com` subdomain patterns. HTTPS is the default; HTTP, local network addresses, and subdomains of a non-wildcard allowlist entry need their explicit manifest flags. Every redirect is checked again. The request limit is 10 MiB, response limit is 20 MiB, default timeout is 30 seconds, and at most five redirects are followed. Browser `fetch` remains unchanged and is **not** governed by this allowlist.

With `allowLocalNetwork: false`, a hostname that resolves to a mix of public
and non-public addresses is rejected with `network_url_not_allowed`. Android
and Windows use a direct connection for this API.

`mini.network.getStatus()` returns only `{ online, type, metered }`; it never exposes network names, addresses, or hardware identifiers. Android and Windows provide the controlled request API and status. Both emit `network.statusChanged` only when this normalized state changes and unregister their system listener when the mini-app closes. Windows currently reports `type: "unknown"` and `metered: false` because the WinForms host does not expose a stable richer classification.

File handles remain opaque and scoped to one mini-app. Both hosts support `files.pickMultiple`, `files.getInfo`, `files.readChunk`, `files.readTextChunk`, and `files.releaseMany`; chunks are bounded to 1 MiB. Both hosts also support user-selected directory handles: `pickDirectory`, `listDirectory`, `openInDirectory`, `createInDirectory`, `writeChunk`, `flush`, `persistDirectory`, `restoreDirectory`, and `forgetDirectory`. Directory paths must be relative and cannot contain traversal segments. The legacy whole-file methods retain their existing 5 MiB guard.

Android accepts `sequential: true` on `files.readChunk` for consecutive
ranges of a large selected file. It reads on a background worker and keeps
one input open per mini-app. Changing the file or requesting a previous
offset reopens the stream. Releasing the active file or closing the app
releases the stream.

The file cloud can call `mini.streams.open({ size, mimeType }, read)` and
`mini.streams.save({ size, mimeType, suggestedName }, read, signal)`.
The runtime exposes both capabilities only to `com.miniapps.telegram-cloud`.
Both hosts request exact blocks through `read(offset, length, signal)` and
accept sources up to 2,000,000,000 bytes. Playback requests up to 512 KiB.
Saving requests up to 1 MiB on current hosts.
`open` returns a temporary local media URL and a `close()` method.
The WebView fetches HTTP ranges from its own host process.
`save` requires `files.save` and prompts for a destination. Windows stages
the data beside the destination and commits it after the full write.
Android creates a document and attempts to delete it on a failed or cancelled
transfer. On either host, closing the app cancels the pending stream reads.

The cloud can save to a picked folder by passing a `directoryId` and optional
`folders` array of relative path segments to `mini.streams.save`. Check
`mini.runtime.supports('streams.saveInDirectory')` before calling this form.
It also requires `files.directory`. The host creates missing subdirectories
within the selected directory and saves each file separately. Folder transfers
use `files.listDirectory(id, { limit, cursor })` and pass the returned
`nextCursor` until it is null. `files.releaseDirectory(id)` drops the
window's handle after use.

Call `telegramCloud.getThumbnail` and `telegramCloud.cacheThumbnail`
through `mini.functions.call` to use the Cloud's bounded session-scoped
cache. On Windows, `telegramCloud.setToolbar` takes
`{ connected, hasChannel, channelTitle, folder, view, sort, hasTransfers }`.
It exposes the path and catalog settings. The window emits
`folder:<path>`, `view:<value>`, `sort:<value>` and `transfers`
through `ui.topBarAction`. An empty path identifies the channel root.

`telegramCloud.showContextMenu` takes `{ kind, canShare, canDownload }`.
It opens the native Windows menu at the pointer for `background`,
`file` or `selection` and returns whether it was shown. Menu commands
emit `ui.topBarAction`. Use `mini.runtime.supports` to feature-detect the
Windows methods.

`files.getAppDirectory()` returns an opaque, read-only handle for the current mini-app's installed directory. Pass that handle to `files.listAppDirectory(id, { limit })` to list up to 200 immediate entries. Folder entries return another opaque handle which can be listed recursively; file entries return regular opaque file IDs suitable for `getInfo`, `readText`, `readBase64`, `readChunk`, and `readTextChunk`. The API needs no permission, returns no OS path, follows no links outside the installed directory, and rejects writes to these file IDs with `file_read_only`.

Windows supports the same directory-handle methods. A persisted directory stores its host path privately under the user's runtime data; JavaScript receives only a new opaque directory ID after restoration. Chunk writes append at most 1 MiB and flush synchronously before resolving.

Android supports `mini.notifications.requestPermission`, `schedule`, `cancel`, `get`, `list`, and `cancelAll`. `requestPermission` uses Android's `POST_NOTIFICATIONS` prompt on Android 13+. Records are private to the manifest ID and retained after the mini-app runtime closes. Supported schedules are one-time ISO-8601 `at` timestamps, daily/weekly local-time schedules, and `interval` schedules from 15 minutes to seven days. Records are re-armed after device boot. Android alarm delivery is best-effort and system power policies can delay it. Windows notifications remain feature-unavailable.

`clipboard.readText()` requires `clipboard.read`; it returns text or `null`. `ui.alert`, `ui.confirm`, `ui.prompt`, and `ui.toast` use native UI. `haptics.*` requires `haptics` and is supported on Android only. `system.canOpenUrl`, `openUrl`, `openFile`, and `openSettings` require `system.open`; URL opening is delegated to the operating system and permits only `https`, `http`, `mailto`, `tel`, and (Android) `geo`.

Use `mini.runtime.getCapabilities()` or `mini.runtime.supports(name)` before optional APIs. Calls for an unavailable feature reject with a stable error rather than silently succeeding.

File pickers, clipboard reads, permission prompts, and external opening require a recent native user gesture on Android and Windows. Calls made outside that window reject with `user_gesture_required`.

Windows exposes `mini.files.writeChecked(id, { path, base64, expectedSha256 })`
for a single file in a user-selected directory. It requires `files.directory`.
Pass the current file's SHA-256 as 64 hexadecimal characters, or `null` to
create a file at an unused name. Writes are limited to 10 MiB. The host stages
the bytes before publishing them and reports `file_changed` on a conflict.
Use `mini.runtime.supports('files.writeChecked')` before calling it.

`mini.app.getLaunchParams()` returns the current launch context. Android returns `{ reason: "notification", notificationId, payload }` after a notification tap and emits `app.launchParamsChanged` for a running activity. Payload is JSON-only, limited to 16 KiB, and host-owned. Both hosts return `reason: "telegramSignIn"` to Unofficial Telegram during a shared sign-in. Windows returns `reason: "normal"` on regular launches. The provider reads its settings through `telegram.getSettings`. Shared sign-in always receives `testServer: false`. Writes from Unofficial Telegram return `telegram_log_disabled` when file recording is disabled in launcher settings.

## Local device discovery (1.5.0)

`mini.network.discoverDevices({ service, timeoutMs })` finds devices implementing the generic local discovery protocol. `mini.network.requestDevice({ id, path, method, token, body, timeoutMs })` sends bounded GET/POST requests through app-scoped endpoint capabilities. Devices, rather than the host, define command semantics. See [Local device presets](local-devices.md) for the complete contract, limits and protocol.


# Security model

Mini-app JavaScript never receives filesystem paths. The native host validates bridge parameters, manifest-relative paths and ZIP entries; traversal/Zip Slip paths are rejected. Storage and permissions are isolated by stable manifest ID.

Windows ZIP imports stream extracted files through a 50 MiB cumulative limit;
the 20 MiB archive and 1,000-entry limits are checked before or during import.
Replacing a launcher interface stages and validates its files before swapping
directories, and restores the previous interface if the final move fails.

Public storage is portable `storage.json`; private storage is local to the host; secure storage is separately encrypted and excluded from sharing and backup. A new manifest permission is left at `prompt`; removed permissions have their stored decision removed. Permission grants are never transferred to another app ID.

An app declaring `telegram.session` can request access to the single
`telegram.session.v1` record from `com.miniapps.telegram`. The host opens
Unofficial Telegram as the fixed sign-in provider when necessary. The provider
runs the client files and Telegram module bundled with the host. The host
loads neither its editable installed code nor the active launcher theme's
app bar into that provider. The
original WebView receives the session after native consent for that app
and that exact saved record. A consumer cannot set the sign-in result.
The file cloud keeps its existing session handoff. The cloud's encrypted
runtime state stores its fingerprint and the selected channel ID. A changed
record requires new approval. The cloud's channel and streaming methods are scoped to
`com.miniapps.telegram-cloud`. A granted session record lets the recipient
act as the signed-in Telegram account. The native prompt identifies the
requesting mini-app. Only grant it to apps and shared modules you trust.

The file cloud's temporary media URLs contain opaque random tokens and
are scoped to its current WebView. The hosts serve them locally as bounded
audio or video range responses with caching disabled. The cloud obtains
the data through its existing Telegram connection. Saving streamed data
requires the `files.save` permission and the user's native save dialog.

Install/update stages and validates app code before switching the active directory. One rollback copy is kept outside the scanned app tree. Updates and rollbacks preserve the current public storage files. Both hosts replay pending installation bookkeeping from a journal after a successful switch. If an interruption occurs before the switch, recovery restores the previous active directory. Rollback metadata format is `miniapps-rollback`, version 1.

Windows rollback state is under MiniApps/.runtime/rollback/by-id. The host
stores replacement intent under MiniApps/.runtime/package-transactions.
Close all windows of the mini-app before updating, rolling back, or deleting
it. Rollback swaps application code and preserves current user data. The host
moves a legacy rollback slot to the new location when its retained manifest
identifies the same app.

The controlled network API is separate from browser `fetch`. Its manifest allowlist accepts explicit origins and leading subdomain wildcards only; credentials in URLs, unsafe schemes, HTTP unless opted in, and local addresses unless explicitly opted in are rejected. Redirects are checked against the same policy, cookies are not persisted by the runtime, and request/response sizes are bounded. The Android and Windows transports run outside the UI thread. Network status deliberately contains no SSID, IP, carrier, or device identifier.

Android and Windows connect directly to the IP addresses returned by a single
lookup for each new connection. With `allowLocalNetwork: false`, the runtime
rejects the entire DNS result if any address is local, reserved, or multicast.
The original URL host is used for the HTTP authority and HTTPS certificate
validation. The controlled transport bypasses system HTTP proxies.

File IDs are capabilities, not paths. They are opaque, app-scoped, and invalid after release or runtime destruction. System opening receives only an opaque handle or a validated URL; no filesystem path is returned to JavaScript. Clipboard reads need a separate permission. Platform dialogs render supplied strings as text rather than HTML.

The installed-directory capability is read-only and scoped to the current mini-app. It can enumerate only children of that app's installed directory and creates opaque child handles; resolved links that lead outside the directory are not exposed. It requires no user prompt because it cannot access another app or write bundled files.

Android records the last native WebView touch and requires it to be recent (one second) before permission prompts, file and directory pickers, clipboard reads, and system opening. This check is host-side; a mini-app cannot satisfy it by adding a bridge parameter.

Android serves launcher and mini-apps under host-controlled HTTPS origins.
AndroidX WebKit accepts bridge messages from the expected origin and main
frame. Launcher and mini-app HTML are served with frame embedding disabled.
Windows also checks the origin of bridge messages and cancels navigation
away from the expected origin.

Each mini-app has a distinct origin based on its manifest ID. Windows keeps
data from the former shared browser origin separate from the new app
origins. App-native storage continues to use the installed ID. Native network
redirects on both hosts stop forwarding caller-supplied headers after a
cross-origin redirect.

The local peer transport is disabled in release builds. Its development
protocol has no authenticated pairing or encryption and is not suitable for
production transfer of sensitive data.

Android notification records are scoped to the manifest ID. Their payload is JSON-only and bounded to 16 KiB; a notification tap constructs host-owned launch parameters for that same app. Removing an app cancels its alarms and clears its records and directory aliases. Android releases a persisted system folder grant after its last alias and open runtime reference are gone. Windows does not expose notification scheduling or activation.

Generic local-device discovery additionally requires a manifest `discoveryServices` allowlist, `allowHttp`, `allowLocalNetwork`, and the existing `network` permission. The host derives addresses only from nonce-matched UDP responders on a queried private IPv4 subnet and returns app-scoped opaque endpoint capabilities with a 60-second discovery lease. Device requests permit bounded API paths, GET/POST, a restricted token header and form bodies; arbitrary URLs, cookies, proxy use and redirects are excluded. Discovery is unauthenticated and device-generated IDs are not trusted identity. Device presets must implement authorization; HTTP tokens remain plaintext and require a trusted LAN. Android uses a bounded direct socket for discovered endpoints without enabling global application or WebView cleartext access. Peer transport release gates remain unchanged.


# Shared modules and Telegram

## Shared JavaScript modules

Ordinary consumers such as Shopping List and Telegram Cloud load the
shared Telegram module from the installed `MiniApps` directory. To replace
this copy, put its files in the directory shown below, then reopen the
consumer. The host loads **Unofficial Telegram**, the sign-in provider, and
its Telegram module from the host bundle. Editing files under `MiniApps`
changes the shared copy for ordinary consumers only.

```text
MiniApps/
└── Modules/
    └── telegram/
        ├── index.js
        └── THIRD-PARTY.txt
```

Windows uses the `MiniApps` subfolder beside `MiniApps.exe`. Android uses
`/storage/emulated/0/MiniApps`. The Windows installer and Android APK include
the shared module, **Unofficial Telegram**, Telegram Cloud and Shopping List.
Both hosts apply their bundled mini-apps on startup after installation or an update. Shopping List includes English and Russian
entries in the same package and keeps the existing list on update. On both
platforms, **Settings → Telegram** also offers manual installation of the
bundled client and module with progress and a restart prompt.

```js
await mini.modules.load('telegram');
const telegram = window.MiniAppTelegram;
```

Module IDs match `[a-z][a-z0-9-]{0,47}`. The host serves only the classic script
entry point, up to 16 MiB. Concurrent loads of the same ID share one promise in a document.
An unavailable script rejects with `module_load_failed` and can be retried.
The script publishes its own API on `window`. Reopen the mini-app after
replacing an already loaded module. An invalid ID rejects with `invalid_module_id`.

A module executes in the calling app's document with the same bridge permissions
as that app. It can see its page and any data the app can access. Treat shared
module files as executable code and install them from a source you trust.

## Sign in and use Telegram

1. Create Telegram API credentials under **API development tools** on
   [my.telegram.org](https://my.telegram.org). See [Telegram's API ID instructions](https://core.telegram.org/api/obtaining_api_id).
2. Open **Unofficial Telegram** in MiniApps and enter your API ID and API hash.
   For phone login, also enter the phone number in international format. If
   Telegram sends an in-app code, look for it in the verified **Telegram**
   service chat on a device signed in with the same number. When Telegram
   offers SMS as a fallback, **Запросить код по SMS** becomes available after
   the wait period. **Ответ Telegram** on the code screen shows the delivery
   type, the fallback offered by Telegram, and its timeout in seconds. These
   fields describe the server response. Check the receiving device to confirm
   the message arrived. Use QR sign-in if the message does not arrive and
   Telegram offers no fallback.
   See [Telegram's login code help](https://telegram.org/faq#q-getting-a-code-via-telegram).
   If Telegram switches delivery after a resend, use the new prompt. A code
   can arrive by email, and Telegram can ask you to verify a new address.
   The email screen offers a reset when Telegram provides reset availability
   and shows the waiting date when a reset is pending.
3. For QR login, choose **Войти по QR** on the sign-in or code screen. On a
   signed-in phone, open **Settings → Devices → Link Desktop Device** in
   Telegram and scan the displayed QR code. The code is generated locally and
   changes when it expires. MiniApps checks the login again when the code
   refreshes and when you return to it on Android. This lets it pick up the
   confirmation and show the two-step verification password prompt if the
   scan notification arrived late.
   See [Telegram's QR login flow](https://core.telegram.org/api/qr-login).
4. Open a chat to load and mark the displayed messages as read. Use **Обновить**
   to fetch new messages, **Загрузить предыдущие** for older history and
   **Отправить** to send a text message. The mini-app supports personal chats and
   groups. Attachments appear as placeholders. Broadcast channels require
   sponsored-message support under [Telegram's API terms](https://core.telegram.org/api/terms).

The module uses [teleproto](https://github.com/sanyok12345/teleproto) over secure
WebSocket connections to Telegram data centers. This is the browser's WebSocket
transport. The app's Content Security Policy limits its network connections to
`wss://*.web.telegram.org`.

### Test server

In the launcher, open **Settings → Telegram** and enable **Telegram test server**.
Then open **Unofficial Telegram** directly. Use an account registered in Telegram's separate test
environment, for example one open in Telegram Beta with **Test Backend**
enabled. Enter the code from a test session or scan the QR with that session.
The same bundled or manually supplied API credentials can be used in both
environments. See [Telegram's test environment](https://core.telegram.org/bots/features#dedicated-test-environment).

The test mode has its own saved session, re-entry tokens, service notices and
rate-limit deadline. The client verifies the test server before requesting a
code. The setting is off by default and applies the next time you open
Unofficial Telegram. Turn it off to return to the regular server.
Sign-in opened by the shopping list or file cloud continues to use the
regular account.

Unofficial Telegram sends the host's Windows or Android version and the
installed client version in the MTProto connection metadata. The connection
sends `en-US` as `system_lang_code`. The sign-in log includes the OS and
client versions in `telegram.connection.profile`.

### Sign-in log

Before requesting a login code or using QR, enable **Save Telegram login log
to file** in the launcher under **Settings → Telegram**. After the attempt,
open **Telegram login log** in the same tab to view or copy the latest 80
recorded Telegram login events. These include the platform, connection,
data center, request timing, Telegram response, and QR progress. Use
**Refresh log** to reload the display. File recording is off by default.
Turning it off leaves existing logs in place. On
Windows, find it under `Data/User/Logs` in the MiniApps installation. On
Android, open `Documents/MiniApps/Logs` in shared storage.
The export contains no phone number, API credentials, login code, QR token,
password, session, or raw Telegram payload. The log can confirm an RPC response.
The response exposes Telegram's selected delivery method, and the API
provides no confirmation that the receiving app displayed the message.

With **Сохранить сеанс на этом устройстве** selected, the mini-app encrypts the
API credentials and session through `mini.secureStorage`. Opening Unofficial
Telegram restores the saved session for the selected server automatically. An
expired session opens the sign-in form. After a temporary connection error,
choose **Повторить подключение** to try the saved session again. Login codes and the
two-step verification password are used during sign-in. When Telegram issues
a future authorization token, MiniApps keeps it in the same protected storage
under a separate key. It supplies saved tokens for the current API ID on
subsequent phone sign-ins when **Сохранить сеанс на этом устройстве** is
selected. Telegram decides whether to accept a token and whether to request
the two-step verification password. MiniApps keeps up to 20 tokens in total.
**Выйти** ends the Telegram session and keeps the tokens for the next login.
**Удалить сохранённый вход** removes the local session and tokens. After
logging out, use **Удалить токены повторного входа** to remove the tokens
separately. Use Telegram's device settings to revoke a session when Telegram
does not confirm logout.

Unofficial Telegram shows unconfirmed devices and lets you confirm or revoke
each new session. Login codes in the service chat are hidden from chat
previews. On Android 14 and later, a screenshot detected by the system while
the chat is visible requests invalidation of visible login codes. Windows
and older Android versions protect the chat window from ordinary OS capture.

Install the current MiniApps host together with the Telegram module and both
mini-apps. One Telegram window in an installation can connect at a time.
Close the connected window to use the saved profile from the other mini-app.
This keeps the saved login available for the next window.
The installation keeps Telegram's rate-limit deadline across window closes.
If the server returns a wait, the current queue pauses and resumes after the
specified time. The app displays the wait and keeps file saves cancellable.
Telegram service notices are shown in the current mini-app and kept in the
encrypted local history for Telegram Notifications.

## Bundle API credentials

For a build that should use a predefined Telegram API ID and hash, copy
`Build/Telegram/api-credentials.example.json` to
`Build/Telegram/api-credentials.local.json` and fill in `api_id` and
`api_hash`. Build Windows or Android with the usual platform script.
The local file is excluded from Git. The credentials are part of the
resulting distribution and can be extracted by someone who receives it.

Unofficial Telegram uses valid bundled credentials for new sign-ins and
offers a button for manual entry. When the file is absent, malformed,
or rejected by Telegram, the login screen shows the API ID and hash
fields. A saved account continues using the credentials with which it
signed in. Telegram login codes, passwords, and sessions stay out of
the build file.

## Sign in from another mini-app

Open the Telegram feature in the requesting mini-app and choose its sign-in
button. If the runtime has no saved account, it opens **Unofficial Telegram**.
Use the instructions under **Как получить API ID и API hash** to get the
developer credentials. Sign in by QR or phone. MiniApps saves the session,
closes the sign-in window, and asks whether the original mini-app may use the
saved account. Later apps can use that same account after their own approval.

## Sync the Shopping List

1. Create a private broadcast channel for the list, with auto-delete and
   content protection off. Give both Telegram accounts permission to post.
2. Open **Shopping List → Settings → Telegram sync → Connect Telegram**.
   You can also open setup with **Sync** at the top of the list if no channel
   is selected. Sign in if prompted, search for the channel by name, and select
   **Use this channel**. The app checks posting access, auto-delete and content
   protection before saving the channel. Repeat on the second device with the
   other account and the same channel. To switch later, select **Change channel**.
3. Select **Sync** at the top of the app. A new channel receives the current
   list. When joining an existing channel, the app imports the shared list
   and merges local edits. Local shopping continues when signed out or offline.

The mini-app searches the selected channel for `#miniapps_shopping_list`.
One Telegram post contains the selected purchases and purchase marks in its
caption, with a JSON attachment for synchronization. If the caption reaches
Telegram's limit, the attachment still contains the complete shared list.
The attachment includes stable IDs, the latest change to each shared field,
and removal records. An unchanged shared list can reuse the existing post.
One sync downloads up to 8 MiB of unique shopping-list snapshots. If the
channel exceeds that budget, the app reports the limit and keeps the local list.

Each device keeps its product catalog, category layout and appearance settings
locally. Received purchases appear in the normal **Purchases** list and add
any missing products or categories to **Goods**. Matching catalog products
reflect the shared selection and purchase marks. Removing a purchase clears
its selection and keeps the product in the catalog. Matching names within
the same category are combined, and removal records keep an offline copy
from restoring a previously removed purchase.

Sync reads the current purchase JSON attachment. Earlier text snapshots and
full-catalog attachments are skipped and stay in the channel.

After the first successful channel lookup, Shopping List remembers the selected
channel for the current Telegram login. Later syncs go straight to that channel
and recheck its settings and posting rights. If Telegram rejects the saved
channel reference, or the user signs in again, the app looks up the channel in
the dialogs and refreshes the reference.

The app writes and confirms a merged snapshot before cleaning up older
snapshots that it contains. Cleanup verifies that the retained publication
still exists. Each account deletes only its own older snapshots. An older
publication by another participant stays in the channel until that person
selects **Sync**. Simultaneous writes can also leave several valid snapshots
until the next sync. Leave at least one valid
list publication in the channel to preserve changes for offline devices.

## Schedule messages

Open **Unofficial Telegram** in MiniApps and sign in to your personal account.
In **Запланировать**, enter text, use **Прикрепить файлы** for documents,
select the chats, and set the send time in your device's time zone. Use
**Добавить день** to schedule the same message and files on more dates.
The button starts with the next calendar day, and you can edit each date
individually. Every selected day uses the same local clock time.
Search includes archived dialogs and Saved Messages. The app supports
personal chats, groups and channels where you have posting rights.
Review the dates, time and recipients in the confirmation dialog. Telegram stores
each confirmed schedule and sends it even after MiniApps closes.

A batch can target up to 10 chats and create up to 30 deliveries. Each
chat on each day counts as one delivery. You can attach up to 10 nonempty
files of up to 2 GB each, subject to Telegram's account and chat limits. Several
files form one grouped document message. The app allows up to 4096 text
characters or 1024 for an attachment caption. Leave time for the upload and
the batch. Each scheduling request needs at least 45 seconds of lead time
to avoid Telegram's immediate-send window. If Telegram reports a wait that
would push the request past that margin, the batch stops. The result lists
the outcome for each chat and date. Retrying the current draft submits
only deliveries that were rejected or still pending. If authentication expires
mid-batch, the open window keeps the draft and confirmed results for the same
Telegram account and server. If Telegram did not
confirm a delivery, check the queue before planning it in a new draft.

In **Отложенные**, the app checks each accessible dialog, including the
archive, for messages in Telegram's queue. This includes schedules created
in other Telegram clients. Cancel a single message or document group, a
chat's queue, or all checked queues. The last two actions refresh the
relevant queues before confirmation. Unavailable or unverified chats are
reported separately. **Остановить проверку** stops the queue scan.

The dialog list is cached in the connected window for two minutes and
per-chat queue snapshots for one minute. An explicit refresh revalidates
queues using Telegram's history hashes. Scheduled-message updates refresh
the visible cache and invalidate the affected snapshot. The app keeps
queue contents and attachment handles in memory. It uploads each
selected file once per batch, uses sequential requests and applies
Telegram's reported flood and slow-mode waits. A server spam or account
restriction stops the scheduling batch and blocks further scheduling in
that connection. Use the feature for chats expecting your messages and
follow [Telegram's spam rules](https://telegram.org/faq_spam).

To get an updated scheduling client, install a MiniApps build containing the
new bundled provider. The app requests the native file-picker permission
when you attach a file.

## Use a private channel as a file drive

1. Sign in to **Unofficial Telegram** with **Сохранить сеанс на этом устройстве**
   selected. Open **Облако файлов** in the same MiniApps installation, choose
   **Использовать сохранённый вход** and allow access in the MiniApps dialog.
   After approval, the cloud opens the saved account and last selected
   channel automatically. A changed saved session requires fresh approval.
   If the session expired, sign in again in Unofficial Telegram.
2. Open **Выбрать канал** in the three-dot menu and search by channel name.
   Select a private broadcast channel you own or administer with posting rights.
   The full-width catalog loads more entries as you scroll, including documents
   and photos. A caption such as `Folder^asdf^IMG.jpg` places `IMG.jpg` in
   `Folder/asdf`. The app also reads caret paths from filenames without
   captions and folder-only captions with a slash or backslash from earlier
   builds. A plain caption leaves the attachment in the channel root.
3. The toolbar path starts with the channel name. Select it to return to
   the root or select a folder in the path to go up. **Назад** dismisses
   the open menu or dialog first. In the catalogue it goes up one folder.
   From the root or the initial screen it returns to the MiniApps launcher.
   Use **Вид** and
   **Сортировка** in the three-dot menu to change the catalog. The catalog sorts the
   loaded entries by name, date or size, with folders before files. Filenames
   and the size/date labels use fixed-height single lines. Hover over a
   card for its full name. Each vertical mouse wheel signal scrolls the
   catalog by one row. For staggered tiles, a row is a group of as many
   consecutive cards as there are columns. The catalog animates wheel
   movement even when system animations are disabled. Tiles
   show thumbnails embedded in Telegram messages or available in the local
   cache as soon as the tiles enter view. A sharper thumbnail replaces the
   first frame in the background. The app reuses the media reference from
   the loaded catalogue and refreshes the message only if the reference
   expires. Both tile views place each card in the shortest
   column and repack the cards when the window width or a preview size
   changes. Each tile's preview area follows the thumbnail's proportions
   and shows the whole frame edge to edge. When Telegram offers
   both resized and square-cropped thumbnails, the app prefers a resized
   frame. It caches up to 256
   thumbnails on disk, scoped to the approved saved session. Protected
   thumbnails stay in memory. Auto-deleting messages are excluded from the
   cloud catalogue and thumbnail cache.
   If Telegram provides no usable thumbnail, the app can generate one
   from a supported image up to 32 MiB when its tile enters view. Other
   entries display file-type icons. Open a file for a larger preview.
   The header shows the Telegram post date alongside the filename and size
   when the timestamp is available.
   The viewer first shows a cached or embedded thumbnail when available.
   It replaces that image after decoding the original in the background
   for supported images up to 64 MiB.
   While the original loads, the status appears beside the preview title
   without changing the height of the image area. The viewer shows decoded
   portions of JPEG, PNG and WebP over the cached or embedded thumbnail as
   bytes arrive, when supported by the WebView. WebP partial frames require
   the WebCodecs image decoder. Other WebViews show the thumbnail until the
   full WebP loads. Undecoded areas with no thumbnail pixels are black.
   Progressive JPEGs can gain detail across the whole frame.
   For larger images and other documents, it uses the available Telegram
   thumbnail, including embedded low-resolution thumbnails.
   A large text file shows its first 64 KiB. Video and audio use the
   device's web player and request ranges as playback or seeking needs them.
   Images and video fill the available window while preserving their
   proportions, including when enlarged. The toolbar icon switches to
   original preview dimensions and back. Larger media can scroll in
   original-size mode. Use the left and right arrows or swipe horizontally
   to browse the loaded images and videos in the current folder, in its
   current sort order. Zoom the media with the wheel or a pinch. Ctrl+wheel
   follows the host's interface zoom. Drag enlarged media
   with the left mouse button or a finger to pan it. Videos start on open
   and a click or tap on the picture toggles play and pause. If autoplay
   with sound is blocked, the player
   starts muted and the toolbar offers a sound button.
   Playback depends on the formats and codecs supported by WebView or
   WebView2. **Скачать на устройство** saves files up to 2 GB in parts.
   Protected content has a preview and the save action is unavailable.
4. **Загрузить файлы** posts the files you select directly to the open cloud
   folder. For a supported image up to 64 MiB, the app generates a JPEG
   thumbnail up to 320 px on the long edge and attaches it to the same
   Telegram document as the unchanged original. The catalogue can load
   that thumbnail directly. The viewer still opens the original when
   available. You can also drag files and folders into the cloud window. The
   drop indicator shows the destination and files inside dropped folders keep
   their relative paths. Empty folders can be added with **Создать папку**.
   On Android, the file manager and WebView must support external file drops.
   **Загрузить папку** creates a subfolder with the source folder's name
   and preserves the paths of its files. **Создать папку** saves an empty folder
   in the selected channel so it can be reopened and used as an upload destination.
   The folder menu opens from the three-dot button or by right-clicking empty space.
   Each uploaded file must be
   nonempty and at most 2 GB (2,000,000,000 bytes). The app reads the file
   in ranges and follows the account's Telegram upload limits. For files of
   at least 16 MiB, it uploads up to four parts at once using Telegram's
   maximum upload part size of 512 KiB. If a batch
   stops partway through, the queue retains the files awaiting confirmation.
   The app checks channel history before sending and skips files with the same
   destination folder, name, and byte size. A match can also come from a file
   already published earlier in the same batch.
   The catalogue, upload check, folder picker and download preparation share
   the same history pages in memory, including pages still being fetched.
   Channel updates and confirmed writes update the cache. If upload
   confirmation is lost, the next check refreshes the recent history.
5. **Скачать папку** saves the contents of the open folder, including nested
   files from older entries, to a directory you select. Transfers use up to
   2 GB per file and report skipped protected files and failed saves.
   Downloads to disk use 1 MiB blocks from Telegram and write as data arrives.
6. Right-click or hold a file to rename it, move it, delete it, or forward
   its message to a Telegram chat. Renaming and moving store the new cloud
   path in the Telegram caption and retain the previous caption text. These
   actions require permission to edit the original post. Deletion asks for
   confirmation and removes the post from the channel. Telegram's forwarding
   restrictions apply to protected files. Use the checkboxes next to the
   dates to select several files in the same folder, then open the menu on one
   of them to move, delete, forward, or download the selection to a directory.
7. **Передача** in the three-dot menu opens while a download or an upload is
   active, or when an interrupted upload is waiting to be retried. One upload
   and one download can run at the same time. Select the direction when both
   are present. The progress bar uses the number of files processed, including
   the current file's partial progress. Downloads first collect the file list
   to determine the total. **Повторить** continues the pending upload queue
   in the current window and checks again for existing files before sending.

The cloud borrows the saved account from the same MiniApps installation.
The runtime remembers approval for that exact session and the selected
channel. If there is no saved account, the cloud sign-in button opens Unofficial Telegram and returns after login. Closing the cloud disconnects its current window from Telegram.

## Rebuild the module

Run `Build\Telegram\BuildModule.cmd` from the repository root with Node.js and
npm installed. It uses the pinned lockfile to regenerate the browser bundle
and its third-party notices. The build adds a range reader and a large-part
option to the pinned Teleproto uploader while retaining checksums and retries.
The host build scripts use the checked-in bundle.


# Windows launcher

See [Windows distribution](windows-distribution.md) for the installer layout and prerequisites.

The Windows application is a small .NET/WinForms shell around the system Microsoft Edge WebView2 Runtime. It does not ship Chromium.

Run Build/Scripts/BuildWindows.cmd from the repository root. It restores the
Windows SDK reference pack, publishes the framework-dependent portable
layout, and builds Output/Windows/MiniAppsSetup.exe with Inno Setup 6.

Setup checks for x64 .NET 10 Desktop Runtime and Microsoft Edge WebView2
Runtime. An offline installation works on a machine that already has both.
The default directory is %LOCALAPPDATA%/MiniApps.

Publishing preserves installed applications, custom interfaces, Config,
Data/User and Data/WebView2/UserData. Bundled applications are shipped as
archives under Data/BundledMiniApps and are applied by the host at startup.
Permission files are stored under Config/Permissions/by-id.

The launcher UI is loaded from `Interface/<name>/index.html`. Interfaces packaged with the application come from `DefaultContent/Interface`, where each interface is a separate subfolder (for example, `DefaultContent/Interface/default`). Custom HTML, ZIP, and folder interfaces can be selected in the launcher settings.

The native launcher exposes `launcher.list()`, `launcher.getAppInfo(id)`, `launcher.open(id)`, `launcher.openNewWindow(id)`, `launcher.refresh()`, `launcher.importApp()`, `launcher.deleteApp(id)`, `launcher.shareApp(id)`, `launcher.shareAppData(id)`, `launcher.getSettingsInfo()`, `launcher.listInterfaces()`, `launcher.selectInterface(id)`, `launcher.importInterface()`, `launcher.getInterfaceSettings()`, and `launcher.setInterfaceSettings(settings)` to this interface. `shareApp(id)` creates a standalone HTML when the installed app is already a self-contained HTML with an embedded manifest; otherwise it creates a ZIP of its code. It excludes all user data, including `storage.json`. `shareAppData(id)` exports only that app's public `storage.json`; private and secure storage remain excluded. `getInterfaceSettings()` reads the active interface's `Interface/<id>/settings.json` and returns `{}` for a missing or malformed file. `setInterfaceSettings()` accepts a JSON object only, limits its UTF-8 serialization to 64 KiB, and atomically replaces that file; the host derives the active interface path itself. `launcher.getAppInfo(id)` returns the app manifest, installation and update timestamps, and application/data size breakdown. Windows share actions copy their text/file payload to the clipboard.

Trusted launcher interfaces can also call `launcher.getRollbackInfo(id)`, `launcher.rollbackApp(id)`, and `launcher.deleteRollback(id)`. An update retains one previous app directory and source under `MiniApps/.runtime/rollback/by-id`. Rollback swaps source versions but deliberately does not roll back public, private, or secure data. `launcher.getAppPermissions(id)`, `launcher.setAppPermission(id, permission, state)`, and `launcher.resetAppPermissions(id)` manage manifest-declared permission decisions. These management methods are never available to mini-app JavaScript.

Backup APIs are reserved in the shared launcher contract, but native backup/restore file dialogs and restore execution are not implemented yet. Feature-detect `backup.restore` before presenting it in an interface.

## System APIs

Windows supports controlled `mini.network.request`, network status events, multiple-file and directory handles, clipboard read, native dialogs/toast, and validated external URL/file/settings opening. Network requests are allowlist-controlled and cookie-free. Directory paths are never returned to JavaScript; persisted directory paths remain in local runtime data.

Windows haptics and persistent notification scheduling/activation are unavailable and are reported as such by `mini.runtime.getCapabilities()`.

## Windows window controls

- Click an app card to open it in the main window.
- Right-click an app card for the launcher context menu, including **Open** and **Open in new window**.
- Middle-click an app card to open it in a new window.
- The main-window app view has a **← Back** button that returns to the launcher.
- If at least one additional app window is open, closing the main window hides it in the notification area instead of exiting. Double-click the tray icon, or select **Open**, to restore it. Select **Exit** in the tray menu to exit explicitly.

## Native top bar API

Each mini-app receives a native top bar. An interface-specific configuration can be placed in `Interface/<name>/appbar.js`; it calls `mini.ui.setTopBar(config)` after the page loads. The Windows host draws the bar and reserves its height above the WebView, so page content never overlaps it.

`config` supports `visible`, `height` (40–120 px), `paddingX`, `paddingY`, `titleFontSize`, `title`, `background`, `foreground`, `accent`, `showBack`, `backText`, `backButton`, and up to four `actions`. Colors use `#RRGGBB`. An action has `id`, `label`, and optional `accent`; handle its click in the mini-app with `mini.events.on('ui.topBarAction', handler)`.

The `backButton` object keeps the complete appearance of the back button in the interface layer: `radius` (0–48 px), `paddingX` (4–48 px), `background`, `hoverBackground`, `foreground`, `border`, `borderOpacity` (0–255), and `fontSize` (7–20). The Windows host renders these settings with its own lightweight control, rather than a system `Button`, so rounded corners do not leave a rectangular or black background.

## Windows taskbar title

Use `await mini.app.setWindowTitle('My mini-app')` to set the title of the active mini-app window. Windows displays this title in the taskbar, Alt+Tab, and the window caption. The launcher restores its own title when the mini-app is closed.


# Windows distribution

## Build

Run `Build\Scripts\BuildWindows.cmd` from the repository root to create
`Output\Windows\MiniAppsSetup.exe`. The build requires .NET SDK 10 or newer
and Inno Setup 6. The script restores NuGet dependencies before publishing.
The first build needs access to the package sources.

Use `Build\Scripts\BuildAll.cmd` to build both platforms. For Android APK
signing and bundle options, see [Requirements](README.md#requirements).
Build intermediates go to `Cache` and distributable artifacts go to `Output`.

For unattended builds, set `MINIAPPS_NO_PAUSE=1` for an individual platform
script or `MINIAPPS_NONINTERACTIVE=1` for `BuildAll.cmd`.

## Installed layout

The Windows installer lets the user choose a writable folder. If its path does not already contain `MiniApps` as a folder name, the installer adds the final `MiniApps` folder.

```text
MiniApps/
|- MiniApps.exe
|- MiniApps/                 installed mini-apps and shared modules
|- Interface/                launcher interfaces
|  `- default/
|     `- index.html
|- Data/                     runtime files and private application state
|  |- BundledMiniApps/       bundled app archives applied on startup
|  |- WebView2/              WebView2 loader and managed-library XML documentation
|  |  `- UserData/           WebView2 profile
|  `- User/                  private and secure mini-app storage
`- Config/                   launcher configuration
   |- window-sizes.json
   |- launcher-interface.txt
   `- Permissions/           permission files keyed by app ID hash
```

The uninstaller files `unins000.exe` and `unins000.dat` are stored in `Data`.

## Packaged content and offline updates

The installer updates the selected installation offline when .NET Desktop Runtime and WebView2 are already installed.

- The Windows executable is published once. Inno Setup stages the same packaged content used by the portable output. The build excludes mini-app test and tool folders, source snapshots, public storage and runtime state. The staging directory also excludes local configuration, WebView2 profile, private data and custom apps or interfaces. Before Inno Setup runs, the build verifies that the executable, the default interface, and at least one bundled application archive are present.
- Inno Setup writes into `Cache/Windows/installer-output`; `Output/Windows/MiniAppsSetup.exe` is replaced only after compilation succeeds. An interrupted publish restores saved configuration and WebView2 profile data on the next run.
- Setup ships bundled archives in `Data/BundledMiniApps`. At startup the host validates and applies them through the normal package installer. It preserves public storage, user-added apps, permission decisions for retained capabilities, and eligible previous versions. Setup also refreshes packaged interfaces while preserving additional custom interface folders.
- Runtime binaries and libraries are refreshed in `Data`; `Data/User` and `Data/WebView2/UserData` are preserved. `Config` is also preserved, including window size, selected interface, and mini-app permission settings. Imported ZIP and HTML packages are installed directly and are not retained as source copies.

## Dependencies

Windows setup requires the x64 .NET 10 Desktop Runtime and Microsoft Edge
WebView2 Runtime. It offers the relevant Microsoft download page when a
dependency is missing. For an offline machine, prepare the standalone
Microsoft installers separately.

## Versioning

`Build/version.properties` defines `APP_VERSION` for the Android package, the Windows executable, and the Windows installer. The launcher shows the version embedded in the running app. Android also uses `ANDROID_VERSION_CODE` for package updates.
